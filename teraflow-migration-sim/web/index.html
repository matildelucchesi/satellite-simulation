Laboratory

Connecting…

The laboratory really runs TeraFlowSDN 7.0 on two controllers (SAT-A and SAT-B), the Mininet/BMv2 network of the domain and the P4Runtime proxy that assigns authority. Only the controller state migrates: the software is already on board every satellite. One job at a time; the work goes on even if the page is closed.

    Verification

    What the verification does

    1. Prepares the laboratory: starts the controllers, empties the destination database, configures the domain network in TeraFlow and measures the service baseline (API, P4 authority, 10 consecutive pings).
    2. Runs a Hot migration on the first event of the catalogue: the destination gets ready while the source still governs the network, then freeze, delta, verification and handover of authority.
    3. Prepares the laboratory again and runs a Cold migration on the same event: state saved, source stopped, transfer and restore on the destination.
    4. After each migration it checks API equivalence, authority on the destination and service pings, and records downtime and duration.

    It checks the laboratory before an experiment; repeat it after changes to the code or to the scenario.

    Experiment

    What the experiment does

    1. Uses 3 events, according to the chosen policy. Designed events: 1 hop on the same plane, 5 hops on the same plane, 7 hops towards the other plane. Cost policy: on the same shadow entries, the destination where the controller stays available for at least 95% of the stay (measured Hot downtime) with the lowest control latency; an entry with no admissible destination is replaced by the nearest one in time.
    2. First runs a warm-up run, which does not enter the results.
    3. Then repeats each event 3 times in Hot and in Cold, one replica after the other: same path, same orbital instant, laboratory prepared from scratch before every run. In each pair the Hot/Cold order is drawn at random, with the seed recorded.
    4. For each run it measures controller downtime, duration, lost pings and propagation delay of the path; for each event it computes median, quartiles and Cold − Hot with a 95% interval.

    19 runs in all, about 2 hours. A failed run stays missing and the experiment goes on; it stops if the laboratory needs recovery or after 3 failed runs in a row.

      Scenario

      Preview

      Two real Starlink orbital planes, 53° shell at 463 km. Each satellite has 3 lasers: 2 towards its neighbours on the same plane, 1 towards the other plane. The controller governs a domain of 16 satellites; when its source is about to enter shadow it migrates, possibly over several hops, to a satellite in sunlight. During a job the view follows the run in progress: the orbit stays at T−30 s while the laboratory is prepared, then advances one orbital second per second. Each laser link has the propagation delay of its length. Assumption: before transferring, the path must stay available for 60 s in a row. Modelled geometry, not to scale.
